# class-manager Phase 2 設計計畫：課堂資料採集與回寫

> 狀態：**草案・未動工**，供老師選擇要做哪幾項。
> 上位規則：`Project/AGENTS.md`、`班級事務/CLAUDE.md`、`class-manager/CLAUDE.md`。
> 承接：`docs/設計藍圖與路線圖.md`（Phase 1 六支工具已完工）。

## 0. 這份計畫要解決的事

老師的訴求：**「可量化的」日常行為與課堂表現，在教室當下點一點就進資料庫；
「需要描述情境的」輔導與個案，才用一句話指令交給 AI。**

現況是這條線斷在中間：

- **後台（Notion）** 已有完整的資料庫與週結／報告產線（紀錄庫、銀行、成績、報告、輔導）。
- **對話端** 已有 13 支 class-* skills，一句話就能入庫。
- **教室端（class-manager）** 有 6 支工具，但依 `CLAUDE.md`「寫入分級」規定，
  **Phase 1 全部停在 L1：只寫 localStorage、不新增任何寫入路徑**。

也就是說：老師在教室點的每一下（誰答對、誰沒交、誰掃得好）**現在全部丟掉**，
要進資料庫得下課後再用嘴巴講一次。**Phase 2 的唯一核心，就是把這一段接起來。**

## 1. 現況盤點：後台有什麼 × 教室端能採什麼

| 後台功能（Notion＋skill） | 它需要的「可量化資料」 | 現在怎麼進去 | class-manager 可以怎麼採 |
|---|---|---|---|
| 📝 班經與學習紀錄庫（class-log / R01） | 座號・類別・科目・正負向・程度 | 老師事後口述一句話 | **座位版加分板**、抽籤問答、小組計分 |

| 📊 學生學習報告（class-report） | 五向度分數＝該週紀錄庫彙整 | 紀錄庫夠密才準 | 上述全部都會加密紀錄庫 |
| 📚 學期成績庫（class-grades） | 平時成績 | 上傳成績單／口述 | **隨堂小考登分板** |

| 🧭 學生輔導紀錄（class-counsel / R09） | ABC 觀察的 **B＝行為出現頻率** | 老師靠印象 | **行為計次器**（只計次，情境留給老師講） |
| 🎨 學生作品集（class-portfolio / R13） | 照片＋座號 | 教師專區上傳 | **課堂拍照上傳**（代理已有 `upload_file`） |

1. 老師點名的三項（打掃檢核／出缺席／座位版加分）**全部成立**，而且打掃檢核與現行

2. **出缺席是唯一「後台缺一張表」的項目**，其餘全部有現成的目的地。

## 2. 核心缺口：回寫管線（做什麼工具都得先有這個）

沒有這段管線，**再做十支工具也只是十份 localStorage**。三個方案：

| 方案 | 做法 | 優點 | 缺點 |
|---|---|---|---|
| **A. 複用 `submit_task`** | 收班時把整批事件寫成結構化任務原文，POST 進既有 Apps Script 代理 → 建「📥 任務收件匣」列 → 排程 Agent 依新路由批次入庫 | **後端零改動**（`submit_task` 已存在）；token 不出 Script Properties；完全在 class-manager repo 內完工；沿用收件匣既有的狀態機與錯誤回報 | 入庫延遲最多 30 分（排程週期）；要新增一條路由（觸發第五同步） |
| B. 代理新增 `submit_events` | 改 GAS 代理，直接寫紀錄庫 | 即時入庫 | 代理原始碼在 `class-website/scripts/`，**改它會撞硬規則 1「不碰班網」**；且把 class-log 的程度／金幣公式複製到 GAS＝規則兩份會漂 |
| C. class-manager 自建代理 | 另開一個 Web App | 完全隔離 | 兩份 NOTION_TOKEN、兩套口令、雙份維護——違反 CP 值最高 |

### 建議：**採 A**

理由：符合 PDCA「新流程先手動跑 1–2 輪」與 CP 值最高原則；
30 分延遲對「當天收班、隔天才看報表」的實際用途完全無感；
而且**所有欄位規則仍然只有一份**（class-log SKILL.md），不會分裂。

### A 的資料契約（草案）

收班送出的任務原文，**固定前綴＋JSON**，讓排程 Agent 不必做語意解析：

```
#CM-EVENTS v1
{"tool":"seatboard","date":"2026-09-08","batch":"seatboard-20260908-01",
 "events":[
   {"id":"seatboard-20260908-01-s12-1","seat":12,"cat":"課堂表現","subj":"數學",
    "sign":"+","level":1,"note":"主動上台解題"},
   {"id":"seatboard-20260908-01-s05-1","seat":5,"cat":"作業","sign":"-","level":1,
    "note":"數習未交"}
 ]}
```

- **新增路由 R18「批次事件包」**：命中條件＝任務原文以 `#CM-EVENTS` 開頭。
  執行層級 Sonnet、把關「直接完成（入庫）」——與 R01 同級，因為欄位已結構化、
  沒有語意判斷空間（符合模型無關性原則）。
- **座號→名冊 relation**：由排程 Agent 查 Notion 名冊解析，**payload 只帶座號**
  （硬規則 2：class-manager 一個字都不存姓名）。
- **金幣／程度**一律由 R18 套用 class-log 既有公式，**前端不算錢**（規則只留一份）。
- **防重複鍵＝ `id`（工具×日期×批次×座號×序號）**。收班按兩次、網路重送、
  隔天補送都必須不重複入帳（U44 的教訓：少了對象或時間窗會靜默漏記或重複發錢）。
- **失敗即保留**：送出成功才清 localStorage；`ok:false` 或斷網 → 本機留著、
  標「尚未送出 N 筆」，明天照樣可以補送。

### 憑證擺放（重要，投影場景專屬風險）

代理口令目前存 `sessionStorage`。**教室投影的電腦全班看得到，工具頁絕不持有口令。**
定死：

- **只有工作台 `index.html` 能送出**（收班在工作台按，不在投影工具頁按）。
- 工具頁只負責累積 localStorage，**不 import 任何送出程式碼**。
- 工作台輸入口令時 `type=password`，送出後畫面不回顯；口令永不寫 localStorage。

## 3. 候選功能（依 CP 值排序）

### 🥇 T0 收班回寫管線＋工作台「今日待送」面板 — **前置，必做**

沒有它其他都是空的。工作台新增一區：列出各工具今天累積的事件筆數，
一鍵「收班送出」，顯示成功／失敗／尚未送出。

- 產出：`assets/js/collect.js`（事件模型＋送出）、工作台面板、路由 R18。
- **這一項完成後，下面 T1–T3 各只剩「一支採集介面」的工。**

### 🥈 T1 既有三支工具接上回寫 — **最低成本、當天見效**

工具**已經寫好了**，只差把 localStorage 轉成事件包。

| 工具 | 現有 key | 轉成什麼紀錄 |
|---|---|---|
| 作業清點 homework | `classManager.homework.v2` | 未交→「作業」負向程度1；要訂正→完成 不記；**只送未交** |
| 抽籤問答 quiz | `classManager.quiz.v1` | 答對→「課堂表現」正向程度1（可設門檻：當日答對≥2 才記，避免洗紀錄） |
| 小組計分 groups | `classManager.groups.v1` | 冠軍組全員→「亮點」程度1（對上班級榮譽競賽的既有做法） |

⚠️ **設計要點：不要全部都記。** 一天 27 人 × 4 支工具會把紀錄庫灌成噪音，
學習報告的五向度反而失真。每支工具都要有「什麼才值得成為一筆紀錄」的門檻，
**門檻寫進 SPEC，不留給實作自由心證。**

### 🥉 T2 打掃工作檢核表 `duty.html` — **老師點名第一項，接合最漂亮**

- **畫面**：投影一頁＝一個掃區（外掃區／教室／廁所…），列出該區成員座號卡，
  每張卡三態：`✓ 到位達標`／`△ 到位未達標`／`✗ 未到`。預設全 ✓（例外管理，多數日子 0 動作）。
- **資料來源**：`duties.json`（掃區・成員・要做的事・做好的標準・工具）。
  ⚠️ **卡點**：現行 `duties.json` 只有去識別化姓名、**沒有座號**，class-manager 不能存姓名。
  → 需要班網 sync 端**多輸出一份純座號版 `duties-seats.json`**（無姓名、無職務）。
  **這是 class-website 的改動，不在本 repo，必須另開一張工單。**
- **回寫**：
  - `✓` → 不產生事件（走週結的固定基準，零筆最省）
  - `△` → 紀錄庫「生活技能」負向程度1（週結扣常規獎那天，不扣幣）
  - `✗` → **「打掃缺席」事件**，週結薪水次數 −1（正是 class-bank 現行公式的 `−缺席次數`）
  - 臨時支援 → `+支援次數`
- **價值**：目前這些例外全靠老師記得，漏記＝薪水算錯錢。機械化後**週結金額才真的可信**。

### T3 出缺席紀錄 `attend.html` — **需先在後台開一張新表**

- **後台**：新建 Notion「🗓️ 出缺席紀錄」。欄位建議：
  `日期(date)`／`學生(relation→名冊)`／`假別(select：事假/病假/公假/喪假/遲到/早退/曠課)`／
  `節次或全日(select)`／`事由(text)`／`家長已告知(checkbox)`／`學年(select，必填)`。
- **為什麼不塞進紀錄庫**：出缺席會被獨立查詢（學期統計、通報、期末報表），
  混進紀錄庫會被行為紀錄稀釋，也會污染學習報告的五向度。
- **採例外管理**：每天只點「沒到的人」，一天通常 0–2 筆，一年幾百筆。
  畫面＝座號網格，預設全到，點一下選假別。
- **與 class-bank 連動**：缺席日的打掃／午餐次數自動 −1（不必老師另外記）。
- **個資**：假別與事由屬敏感資訊，**不進班網公開 JSON**，比照 ClassCare 加入 `PII_KEYS` 護欄。

### T4 座位版加分板 `seatboard.html` — **老師點名第三項**

- **畫面**：依真實座位圖投影（講台在上），一格＝一位學生（只顯座號）。
  點一下 `+1`；長按／右鍵開小面板選 類別・科目・程度・正負向。今日累計顯在格子角落。
- **資料來源**：`seating.json`（六排網格）——**同樣只有姓名沒有座號**，
  需 sync 端多出一份 `seating-seats.json`。與 T2 是**同一張班網工單**，一起做。
- **備援**：座號版 JSON 拿不到時，退回「座號連號網格」（1–27 順排），仍可用。
- **護欄**：
  - 投影中**不顯示金額**，只顯示 `+1 / +2`（避免上課變成算錢大會）。
  - **禁止在畫面上排名**（通用鐵則 6：成績不排名；行為分同理不做全班排行榜）。
  - 誤點救援：每格支援「復原上一筆」，收班前都可改。

### T5 每日常規檢核 — **3 秒，養活「班級常規獎勵」**

現行「每天 +1、五天全勤 +3」採例外管理，但**沒人在記例外**，等於全班天天滿分。
工作台加一列：今天有沒有人常規未達成？沒有就按「全班達成」，有就點座號。

### T6 行為計次器 — **直接對上老師「專注在輔導」的訴求**

給正在跑輔導個案的 1–3 位學生用。老師設定要觀察的行為（如「未經允許離座」），
畫面一顆大按鈕，發生就點一下，自動記時間戳。

- 回寫成「輔導觀察事件」，供 class-counsel 的 **ABC 觀察**取得**真實基線頻率**，
  而不是靠印象說「他很常」。
- **這支最貼合老師的原話**：次數交給機器，`前事→行為→後果` 的情境描述留給老師一句話。
- **個資最高等級**：只存座號、只在本機、送出後即清；**永不進班網任何 JSON**。

### T7 隨堂小考登分板 — 分數直接進 📚 學期成績庫的平時成績
### T8 課堂拍照上傳作品 — 代理的 `upload_file` 已存在，接 class-portfolio（R13）

## 5. 需要老師拍板的決策點

1. **管線走 A 案（複用收件匣、延遲 ≤30 分）可以嗎？** 若堅持要即時入庫，就得動 GAS 代理，
   要同時修訂「不碰班網」硬規則的邊界（把代理定義為三站共用後台）。
2. **做哪幾支、什麼順序？** 建議 T0 → T1(作業) → T2 打掃 → T4 座位加分 → T3 出缺席。
3. **出缺席要不要開新 Notion 表？** 開表才查得動統計；不開就只能塞紀錄庫（會污染學習報告）。
4. **每支工具的「入庫門檻」**：例如抽籤問答答對幾次才記一筆？這是教學專業判斷，
   AI 不該替老師決定，但**必須在動工前寫死進 SPEC**（模型無關性）。
5. **座位加分要不要顯示金額**：建議不顯示（見 T4 護欄），請確認。

## 6. 已知踩雷預告（動工時要當檢查表）

- **收班要冪等**：`id` 三段式（工具×日期×座號×序號），按兩次不重複發錢（U44）。
- **零事件的學生 ≠ 不存在**：報表端一律先開空殼再累加（U41）。
- **公開輸出的過濾做在產生端**：出缺席假別／輔導計次**絕不進班網 JSON**（U42），
  前端隱藏只是第二保險。
- **金幣公式只留一份**：一律在 R18／class-log 側計算，前端不算錢。
- **新增路由 R18 會觸發第五同步**：必須同步改 `07_排程Agent_routine_prompt.md`
  並用 `RemoteTrigger` 更新雲端 routine 的 prompt，改完回讀確認 `enabled`／`cron` 沒被動到。
- **班級鐵則 8**：每支工具上線都要同步 `class-manager/docs/老師操作手冊.md`＋Notion 使用說明。
- **完工定義**：push 後**輪詢**到 200／指紋出現（單發 curl 會誤判，U46）；
  1600×900 無溢出（就地 `height:auto` 讀 `scrollHeight`）；390 寬無橫捲；靜態資源版本號往前推。
