## 3. 回寫管線（T0・定案）

### 3.1 走法

收班時把整批事件寫成**結構化任務原文**，POST 進既有 Apps Script 代理
（`class-website/scripts/apps-script-proxy-v2.gs` 的 `submit_task`，token 在 Script Properties、
前端只帶口令；代理網址在公開的 `data/site-config.json`，同源可讀）
→ 建「📥 任務收件匣」列 → 排程 Agent 依**新路由 R18** 批次入庫。

**後端零改動、不碰班網任何檔案、金幣公式只留一份。**

### 3.2 資料契約

```
#CM-EVENTS v1
{"tool":"routine","date":"2026-09-08","batch":"routine-20260908-01",
 "events":[
   {"id":"routine-20260908-01-s12-1","seat":12,"src":"rule",
    "rule_n":5,"kind":"bad","act_i":0,
    "act":"干擾課堂","coin":-5,"level":-1,"period":"上午課堂","note":""},
   {"id":"seatboard-20260908-01-s07-1","seat":7,"src":"tally",
    "kind":"good","act":"抽問答對","count":1}
 ]}
```

- **新增路由 R18「批次事件包」**：命中條件＝任務原文以 `#CM-EVENTS` 開頭。
  執行層級 Sonnet、把關「直接完成（入庫）」——與 R01 同級，因為欄位已結構化、
  沒有語意判斷空間（模型無關性）。
- **座號→名冊 relation** 由排程 Agent 查 Notion 解析；**payload 只帶座號**（硬規則 2）。
- **`src:"rule"` 的 coin／level 是「原封轉抄 `class-rules.json`」不是前端計算**：
  R18 入庫前**回讀 `class-rules.json` 核對 `rule_n`＋`act_i` 的 coin／level 一致才寫入**，
  不一致就標失敗。這樣既不讓前端算錢，又擋住班規改了而工具沒更新的漂移。
- **防重複鍵＝ `id`**（工具×日期×批次×座號×序號）。按兩次收班、重送、隔天補送都不得重複入帳（U44）。
- **失敗即保留**：送出成功才清 localStorage；`ok:false` 或斷網 → 本機留著、標「尚未送出 N 筆」。

### 3.3 憑證擺放（投影場景專屬風險）

教室投影全班看得到畫面，所以定死：

- **只有工作台 `index.html` 能送出**；收班在工作台按，不在投影工具頁按。
- 工具頁只累積 localStorage，**不 import 任何送出程式碼、不持有口令**。
- 口令輸入用 `type=password`，送出後不回顯，**永不寫 localStorage**（只留 sessionStorage）。

## 4. 常規檢核台 `routine.html`（本版新增核心）

老師要把「生活常規班規」一併納入。盤點後發現：**班網公開的 `data/class-rules.json`
已經是一份完整的結構化正本**，不必另外建資料，直接拿來當工具的骨架。

### 4.1 它已經有的三層資料

| 區塊 | 內容 | 在工具裡當什麼 |
|---|---|---|
| `cards`（10 張） | 班規條號・公約對應・`good[]`／`bad[]`（具體行為・幣值・程度・**修復方式 fix**） | **事件目錄**：點一下就帶齊五個欄位 |
| `daily`（8 段） | 早晨入班／環境晨掃／朝會晨讀／上午課堂／午餐／潔牙午休／下午課堂／整理放學，各有 `sop`／`expect`／`redo` | **檢核的時機＝分頁** |
| `flows`（6 個） | 進教室／發材料／上課發言／小組討論／收拾／排隊，各有 `redo` | 當場「重來一次」的指示卡 |

### 4.2 架構：一支工具、八個時段分頁

**不做三支獨立工具**（原 v1 的 T2 打掃檢核＋T5 常規檢核＋班規記錄），
改成一支 `routine.html`，用 `daily` 的 8 個時段當分頁。

每個時段頁面分上下兩半：

- **上半（投影給學生看）**：該時段的 `expect`「做到的樣子」。
  這本身就有教學價值——常規不是貼在牆上的紙，而是每個時段都出現在眼前。
- **下半（老師操作）**：座號網格。點一位學生 → 彈出**該時段相關的班規行為選單**
  （從 `cards` 依 §4.3 對照表過濾，一頁通常 4–8 個選項）→ 再點一下完成。

### 4.3 時段 → 班規對照表（**需老師確認，這是教學專業判斷**）

| 時段 | 主要相關班規卡 |
|---|---|
| 早晨入班 | ① 不遲到、⑦ 管好自己 |
| 環境晨掃 | ③ 打掃要認真 |
| 朝會／晨讀 | ⑤ 上課守秩序、⑦ 管好自己 |
| 上午課堂／下午課堂 | ⑤ 守秩序、⑨ 上課時間、④ 作業用心、② 有禮貌、⑧ 口說好話 |
| 午餐 | ⑦ 管好自己、③ 打掃（餐後整理） |
| 潔牙午休 | ⑦ 管好自己 |
| 整理放學 | ③ 打掃、⑥ 不奔跑、⑦ 管好自己 |
| **任何時段都可叫出** | ② 有禮貌、⑧ 口說好話、⑥ 不奔跑、⑩ 重大安全事件 |

### 4.4 三條設計鐵則

1. **一律例外管理，預設全班達成，老師只點例外。**
   多數時段是 0 動作。若要老師每個時段點 27 個人，這支工具一週就會被放棄。
2. **點完當場顯示「修復方式」給學生看。**
   例：`座號12 · ⑤上課守秩序 · 修復：到冷靜區沉澱 5 分鐘`。
   **這是這支工具最大的教育價值**——懲處不是只扣分，當場就講清楚怎麼修復；
   而且 `fix` 文字是老師自己在 Notion 寫的，AI 沒有發揮空間。
3. **不在投影上排名、不做全班排行榜**（通用鐵則 6：不排名；同「禁用 A／B／C 組」的去標籤化精神）。

### 4.5「環境晨掃」分頁＝打掃檢核表（原 T2）

這一頁是特化版，因為它要按掃區分組、且要產生**薪水次數的例外**。

- **畫面**：一頁一個掃區，列出該區成員座號卡，三態：
  `✓ 到位達標`／`△ 到位未達標`／`✗ 未到`。預設全 ✓。
- **回寫**：
  - `✓` → **不產生事件**（走週結的固定基準，零筆最省）
  - `△` → 班規 ③ bad「負責的區域沒掃乾淨」−5 幣、修復「下課回去重掃到通過檢查」
  - `✗` → **打掃缺席事件**，週結薪水次數 −1（正是 class-bank 現行公式的 `−缺席次數`）
  - 臨時支援 → `+支援次數`
- **卡點**：`duties.json` 只有去識別化姓名、**沒有座號**，而 class-manager 一字不存姓名
  → 需班網 sync 端多輸出純座號版 `duties-seats.json`（見 §7 工單）。
  **拿不到時退回一般座號網格**，工具照樣可用（只是少了掃區分組）。
- **價值**：現在這些例外全靠老師記得，漏記＝薪水算錯錢。機械化後**週結金額才真的可信**。

### 4.6 類別對照（寫進 SPEC，不留給實作自由心證）

| 班規卡 | class-log 類別 |
|---|---|
| ③ 打掃認真 | 生活技能 |
| ④ 作業用心 | 作業 |
| ⑤ 上課守秩序、⑨ 上課時間 | 課堂表現 |
| ② 有禮貌、⑧ 口說好話 | 人際互動 |
| ① 不遲到、⑥ 不奔跑、⑦ 管好自己 | 生活指導 |
| ⑩ 重大安全事件 | 生活指導・**金幣 −200 定額、不算程度**（比照 class-log 定額項目規則） |

## 5. 晨間報到板 `checkin.html`（出缺席的新解法・可行性評估）

老師的想法：**學生到校自己報到，超過時間沒報到就算遲到。**

### 5.1 結論：**可行，建議做，但定位要改名**

不要叫「出缺席系統」，叫**「晨間報到板」**。三個功能，第三個價值最大：

1. 每天 30 秒完成到班確認；
2. 自動產生**遲到候選名單**給老師確認；
3. **自動累積「一整週都沒有遲到 +10 幣」**——班規 ① 的 good 項，
   目前完全沒在發，因為沒人有資料可以算。

### 5.2 做法

門口一台平板（或教室電腦）開 `checkin.html`：座號網格，學生到校**按住自己的格子 1 秒**完成報到。
純 localStorage、離線可用、只有座號與時間戳，完全符合硬規則 2 與 4。

**動線設計比程式更重要**：依 `class-rules.json` 的 `daily` 早晨入班 SOP
「掛書包 ➜ 抄聯絡簿 ➜ 交作業 ➜ 回座」，**報到插在「交作業」那一步**，
孩子本來就要走到那裡，不額外增加動線，也不會塞車。

### 5.3 五個必須設計進去的風險

| 風險 | 對策 |
|---|---|
| **① 代點／誤點**（小四最大風險） | 按住 1 秒才算（防手滑）＋點完變色並播一聲（旁人會注意）＋**點過自己不能取消**（要改得老師解鎖）＋**時間戳全留可查** |
| **② 沒點到 ≠ 遲到** | 請假、公假、去健康中心、被科任叫走都可能沒點。截止後畫面分三欄**未報到（候選遲到）／請假／已報到**，老師把非遲到的移走，**只有留在候選欄的才送出** |
| **③ 裝置塞車** | 格子要大（平板橫放一格 ≥100px）、一秒完成；**Phase 1 先單機**，實測真的塞車再評估雙機（雙機要處理合併，不要一開始就做） |
| **④ 老師忘了開／裝置沒電** | **沒開＝沒有資料，不是全班遲到**。程式必須有「今天未啟用報到」狀態，收班時**不產生任何事件**。這條要寫死進 SPEC，否則某天忘了開就送出 27 筆遲到（U41：沒有資料 ≠ 這個人不存在） |
| **⑤ 公開標籤化** | 截止前只顯示「已報到＝亮／未報到＝暗灰」，**不標紅、不寫「遲到」二字**；截止後自動切老師視角或關閉投影，候選名單只在老師裝置上看 |

**最關鍵的一條是 ②＋④ 背後的同一個原則：機器只產生候選，老師確認才成立。**
這符合通用鐵則 1（排程後 Check 仍須人為把關），也把代點與漏開的傷害上限壓住了。

### 5.4 與班規接合（不必老師另外決定）

`class-rules.json` cards① 已寫死：
- bad「上學遲到」`−5 幣`、fix「補做打掃工作及課堂指定作業」→ 遲到事件自動帶這一組。
- good「一整週都沒有遲到」`+10 幣`、程度 2 → 週結時由報到資料**機械算出全勤名單**。

### 5.5 **Notion 不必開新表**（本版修正 v1 的建議，省一整個工作段）

既然主要只記遲到，而遲到已經是班規 ① 的既有懲處，就直接走紀錄庫：

- 遲到 → 紀錄庫「生活指導」・負向・程度 1・金幣 −5
- 一週全勤 → 紀錄庫「生活指導」・正向・程度 2・金幣 +10

**什麼時候才需要開「🗓️ 出缺席紀錄」表？**
當你需要「本學期遲到幾次」的統計、或要交行政報表時。到那天再開，屆時可從紀錄庫回填。
事假／病假等真正的缺席仍走**老師一句話補登**，不塞進這支工具（那是低頻、需要情境描述的事）。

## 6. ⚠️ 新發現：金幣通膨風險（三題待老師拍板，都與動錢有關）

拍板事項 4（問答一次算一次）與 5（座位板計次）落到 class-log 的既有公式時，
會產生一個 v1 沒算到的問題。依 U44「動錢的自動化先做只算不寫」，先攤開給老師看：

**class-log 公式**：`金幣 = 正負向 × 程度 × 5`。所以「課堂表現 正向 程度1」＝ **+5 幣**。

**試算**：抽問一天答對 20 人次 → 若每次都入帳，一天 +100 幣進入班級；
單一學生一週答對 10 次 ＝ **+50 幣**。對照：打掃薪水一週才 10 幣、商店券 30–60 幣。
**一週就能買兩張券，班級經濟會在兩週內崩掉。**

### 待確認 A：抽問答對怎麼給錢？（建議 ②）

| 選項 | 做法 | 影響 |
|---|---|---|
| ① 照公式 | 每次 +5 幣 | 通膨嚴重，不建議 |
| **② 只計次不入帳（建議）** | 記錄進紀錄庫「課堂表現」正向、**金幣影響 0**；次數照樣累積，學習報告的課堂表現向度照樣長出來 | 保留「一次算一次」的紀錄意義，不動錢 |
| ③ 定額小額 | 每次 +1 幣（比照定額項目，不套 ×5） | 一週約 +10 幣，與打掃薪水同級，可接受 |

### 待確認 B：座位加分板的「輕點 +1」是什麼？（建議：兩種點法分開）

- **輕點＝計次**：格子上的次數 +1，**不入帳**。→ 這正好就是老師要的
  「顯示次數，讓學生知道自己回答的次數有沒有被正確記錄」（拍板 5）。
- **長按＝開班規選單**：帶出 §4.3 的班規項目，**幣值用班規自己的 `coin`**（+5／+10／−5），
  才會動錢。這樣「動錢一定經過班規」，隨手加分不會膨脹。

### 待確認 C：紀錄庫筆數（不影響金錢，但影響查詢成本）

「一次算一次」逐筆入庫的話，抽問一學期約 2,000 筆，紀錄庫一年可能破萬筆
（ER 圖原估「每年約萬筆內」）。Notion 教育版的查詢有配額，週報告要撈整週紀錄。

**建議**：逐筆計次照舊，但**收班時把「同一學生×同一天×同一工具×同類」的計次事件合併成一列**，
事件描述寫「抽問答對 3 次」、次數存欄位。**「一次算一次」的計數完全保留**，
