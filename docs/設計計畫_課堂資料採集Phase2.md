## 3. 回寫管線（T0・定案）

### 3.1 走法

收班時把整批事件寫成**結構化任務原文**，POST 進既有 Apps Script 代理
（`class-website/scripts/apps-script-proxy-v2.gs` 的 `submit_task`，token 在 Script Properties、
前端只帶口令；代理網址在公開的 `data/site-config.json`，同源可讀）
→ 建「📥 任務收件匣」列 → 排程 Agent 依**新路由 R18** 批次入庫。

**後端零改動、不碰班網任何檔案、金幣公式只留一份。**

### 3.2 資料契約

```
#CM-EVENTS v1
{"tool":"routine","date":"2026-09-08","batch":"routine-20260908-01",
 "events":[
   {"id":"routine-20260908-01-s12-1","seat":12,"src":"rule",
    "rule_n":5,"kind":"bad","act_i":0,
    "act":"干擾課堂","coin":-5,"level":-1,"period":"上午課堂","subj":"數學","note":""},
   {"id":"checkin-20260908-01-s03-1","seat":3,"src":"rule",
    "rule_n":1,"kind":"bad","act_i":0,
    "act":"上學遲到","coin":-5,"level":-1,"at":"07:52"},
   {"id":"seatboard-20260908-01-s07-1","seat":7,"src":"tally",
    "kind":"good","act":"舉手回答","subj":"數學","count":3}
 ]}
```

- **新增路由 R18「批次事件包」**：命中條件＝任務原文以 `#CM-EVENTS` 開頭。
  執行層級 Sonnet、把關「直接完成（入庫）」——與 R01 同級，因為欄位已結構化、
  沒有語意判斷空間（模型無關性）。
- **座號→名冊 relation** 由排程 Agent 查 Notion 解析；**payload 只帶座號**（硬規則 2）。
- **`src:"rule"` 的 coin／level 是「原封轉抄 `class-rules.json`」不是前端計算**：
  R18 入庫前**回讀 `class-rules.json` 核對 `rule_n`＋`act_i` 的 coin／level 一致才寫入**，
  不一致就標失敗。既不讓前端算錢，又擋住班規改了而工具沒更新的漂移。
- **`src:"tally"` 一律不入帳**（金幣影響 0），只帶 `count`。見 §6。
- **防重複鍵＝ `id`**（工具×日期×批次×座號×序號）。按兩次收班、重送、隔天補送都不得重複入帳（U44）。
- **失敗即保留**：送出成功才清 localStorage；`ok:false` 或斷網 → 本機留著、標「尚未送出 N 筆」。

### 3.3 收班合併規則（拍板 #10）

送出前，把**同一學生 × 同一天 × 同一工具 × 同一類**的事件合併成一列：

| 來源 | 合併鍵 | 事件描述 | 次數 |
|---|---|---|---|
| 座位板／抽籤問答 | 座號 × 日期 × **科目** × 「舉手回答」 | **「座號N 在○○課舉手回答」**（拍板 #8 指定寫法） | 存「次數」欄 |
| 常規檢核（班規） | 座號 × 日期 × `rule_n` × `act_i` | 「⑤上課守秩序－干擾課堂」 | 同上 |
| 打掃檢核 | 座號 × 日期 × 三態 | 「晨掃未到」等 | — |

- **紀錄庫需新增一個 `次數`（number，選填）欄**——小改動，class-log／class-report 現有欄位不動。
  （替代方案：次數寫進事件描述末尾括號「（3 次）」，零 schema 改動；建議用欄位，報告端好統計。）
- **原始逐筆時間戳仍留在本機 localStorage**，需要細查時看得到。

### 3.4 憑證擺放（投影場景專屬風險）

教室投影全班看得到畫面，所以定死：

- **只有工作台 `index.html` 能送出**；收班在工作台按，不在投影工具頁按。
- 工具頁只累積 localStorage，**不 import 任何送出程式碼、不持有口令**。
- 口令輸入用 `type=password`，送出後不回顯，**永不寫 localStorage**（只留 sessionStorage）。

## 4. 常規檢核台 `routine.html`（核心工具）

盤點後發現：**班網公開的 `data/class-rules.json` 已經是一份完整的結構化正本**，
不必另外建資料，直接拿來當工具的骨架。

### 4.1 它已經有的三層資料

| 區塊 | 內容 | 在工具裡當什麼 |
|---|---|---|
| `cards`（10 張） | 班規條號・公約對應・`good[]`／`bad[]`（具體行為・幣值・程度・**修復方式 fix**） | **事件目錄**：點一下就帶齊五個欄位 |
| `daily`（8 段） | 早晨入班／環境晨掃／朝會晨讀／上午課堂／午餐／潔牙午休／下午課堂／整理放學，各有 `sop`／`expect`／`redo` | **檢核的時機＝分頁** |
| `flows`（6 個） | 進教室／發材料／上課發言／小組討論／收拾／排隊，各有 `redo` | 當場「重來一次」的指示卡 |

### 4.2 架構：一支工具、八個時段分頁

**不做三支獨立工具**（原 v1 的打掃檢核＋常規檢核＋班規記錄），改成一支 `routine.html`，
用 `daily` 的 8 個時段當分頁。每個時段頁面分上下兩半：

- **上半（投影給學生看）**：該時段的 `expect`「做到的樣子」。
  常規不再是貼在牆上的紙，而是每個時段都出現在眼前。
- **下半（老師操作）**：座號網格。點一位學生 → 彈出**該時段相關的班規行為選單**
  （從 `cards` 依 §4.3 對照表過濾，一頁通常 4–8 個選項）→ 再點一下完成。

### 4.3 時段 → 班規對照表（**動工前需老師確認，這是教學專業判斷**）

| 時段 | 主要相關班規卡 |
|---|---|
| 早晨入班 | ① 不遲到（上學）、⑦ 管好自己 |
| 環境晨掃 | ③ 打掃要認真 |
| 朝會／晨讀 | ⑤ 上課守秩序、⑦ 管好自己 |
| 上午課堂／下午課堂 | **① 不遲到（上課）**、⑤ 守秩序、⑨ 上課時間、④ 作業用心、② 有禮貌、⑧ 口說好話 |
| 午餐 | ⑦ 管好自己、③ 打掃（餐後整理） |
| 潔牙午休 | ⑦ 管好自己 |
| 整理放學 | ③ 打掃、⑥ 不奔跑、⑦ 管好自己 |
| **任何時段都可叫出** | ② 有禮貌、⑧ 口說好話、⑥ 不奔跑、⑩ 重大安全事件 |

### 4.4 上課遲到（拍板 #6・#7）

**上課遲到不進報到板，走課堂分頁的班規 ①。** 班規卡 ① 的兩個 bad 項幣值相同、修復不同，
工具依來源自動帶對的那一個：

| 來源 | 行為 | 幣值 | 修復方式（`fix`，點完當場投影） |
|---|---|---|---|
| 晨間報到板 | 上學遲到 | **−5** | 補做打掃工作及課堂指定作業 |
| 常規檢核台・課堂分頁 | 上課遲到 | **−5** | 回教室先向老師報到，下課把落掉的進度補齊，**下課靜坐到遲到的時間**（遲到 5 分鐘就靜坐 5 分鐘） |

→ 上課遲到要記「遲到幾分鐘」時，寫進事件描述末尾（靜坐時間由此而來）。

### 4.5 三條設計鐵則

1. **一律例外管理，預設全班達成，老師只點例外。**
   多數時段是 0 動作。若要老師每個時段點 27 個人，這支工具一週就會被放棄。
2. **點完當場顯示「修復方式」給學生看。**
   例：`座號12 · ⑤上課守秩序 · 修復：到冷靜區沉澱 5 分鐘`。
   **這是這支工具最大的教育價值**——懲處不是只扣分，當場就講清楚怎麼修復；
   而且 `fix` 文字是老師自己在 Notion 寫的，AI 沒有發揮空間。
3. **不在投影上排名、不做全班排行榜**（通用鐵則 6；同「禁用 A／B／C 組」的去標籤化精神）。

### 4.6「環境晨掃」分頁＝打掃檢核表

- **畫面**：一頁一個掃區，列出該區成員座號卡，三態：
  `✓ 到位達標`／`△ 到位未達標`／`✗ 未到`。預設全 ✓。
- **回寫**：
  - `✓` → **不產生事件**（走週結的固定基準，零筆最省）
  - `△` → 班規 ③ bad「負責的區域沒掃乾淨」−5 幣、修復「下課回去重掃到通過檢查」
  - `✗` → **打掃缺席事件**，週結薪水次數 −1（正是 class-bank 現行公式的 `−缺席次數`）
  - 臨時支援 → `+支援次數`
- **卡點**：`duties.json` 只有去識別化姓名、**沒有座號**，而 class-manager 一字不存姓名
  → 需班網 sync 端多輸出純座號版 `duties-seats.json`（見 §7 工單）。
  **拿不到時退回一般座號網格**，工具照樣可用（只是少了掃區分組）。
- **價值**：現在這些例外全靠老師記得，漏記＝薪水算錯錢。機械化後**週結金額才真的可信**。

### 4.7 類別對照（寫進 SPEC，不留給實作自由心證）

| 班規卡 | class-log 類別 |
|---|---|
| ③ 打掃認真 | 生活技能 |
| ④ 作業用心 | 作業 |
| ⑤ 上課守秩序、⑨ 上課時間 | 課堂表現 |
| ② 有禮貌、⑧ 口說好話 | 人際互動 |
| ① 不遲到、⑥ 不奔跑、⑦ 管好自己 | 生活指導 |
| ⑩ 重大安全事件 | 生活指導・**金幣 −200 定額、不算程度**（比照 class-log 定額項目規則） |

## 5. 晨間報到板 `checkin.html`

### 5.1 範圍（拍板 #6）

**只管「上學到校」這一件事。上課遲到不在這裡，走 §4.4 的常規檢核台課堂分頁。**

三個功能，第三個價值最大：

1. 每天 30 秒完成到班確認；
2. 產生**上學遲到候選名單**給老師確認；
3. **自動累積班規 ① good「一整週都沒有遲到 +10 幣」**——目前完全沒在發，因為沒資料可算。

### 5.2 做法：學生自己點，老師只處理例外

門口一台平板（或教室電腦）開 `checkin.html`：座號網格，學生到校**按住自己的格子 1 秒**完成報到。
純 localStorage、離線可用、只有座號與時間戳，符合硬規則 2 與 4。

**老師端一律例外管理**：截止時間到 → 自動鎖定 → 畫面只剩「候選遲到」那幾格要處理，
**沒有例外就 0 動作**（與常規檢核台同一個操作邏輯）。

**動線設計比程式更重要**：依 `class-rules.json` 的 `daily` 早晨入班 SOP
「掛書包 ➜ 抄聯絡簿 ➜ 交作業 ➜ 回座」，**報到插在「交作業」那一步**，
孩子本來就要走到那裡，不額外增加動線，也不會塞車。

### 5.3 五個必須設計進去的風險

| 風險 | 對策 |
|---|---|
| **① 代點／誤點**（小四最大風險） | 按住 1 秒才算（防手滑）＋點完變色並播一聲（旁人會注意）＋**點過自己不能取消**（要改得老師解鎖）＋**時間戳全留可查** |
| **② 沒點到 ≠ 遲到** | 請假、公假、去健康中心、被科任叫走都可能沒點。截止後畫面分三欄**未報到（候選遲到）／請假／已報到**，老師把非遲到的移走，**只有留在候選欄的才送出** |
| **③ 裝置塞車** | 格子要大（平板橫放一格 ≥100px）、一秒完成；**Phase 1 先單機**，實測真的塞車再評估雙機（雙機要處理合併，不要一開始就做） |
| **④ 老師忘了開／裝置沒電** | **沒開＝沒有資料，不是全班遲到**。程式必須有「今天未啟用報到」狀態，收班時**不產生任何事件**。這條要寫死進 SPEC，否則某天忘了開就送出 27 筆遲到（U41：沒有資料 ≠ 這個人不存在） |
| **⑤ 公開標籤化** | 截止前只顯示「已報到＝亮／未報到＝暗灰」，**不標紅、不寫「遲到」二字**；截止後自動切老師視角或關閉投影，候選名單只在老師裝置上看 |

**最關鍵的是 ②＋④ 背後的同一個原則：機器只產生候選，老師確認才成立。**
符合通用鐵則 1（排程後 Check 仍須人為把關），也把代點與漏開的傷害上限壓住。

### 5.4 回寫（拍板 #7）

- 上學遲到 → 紀錄庫「生活指導」・負向・程度 1・**金幣 −5**，
  事件描述「座號N 上學遲到（07:52 報到）」，修復＝班規①「補做打掃工作及課堂指定作業」。
- 一週全勤 → 紀錄庫「生活指導」・正向・程度 2・金幣 +10（週結時由報到資料機械算出）。

### 5.5 **Notion 不必開新表**

遲到已經是班規 ① 的既有懲處，直接走紀錄庫即可，**省一整個工作段**。
什麼時候才需要開「🗓️ 出缺席紀錄」表？當你需要「本學期遲到幾次」的統計或行政報表時，

## 6. 金幣通膨：三題已解決（拍板 #8–#10）

原問題：class-log 公式 `金幣 = 正負向 × 程度 × 5`，課堂表現程度 1 ＝ **+5 幣**。
若抽問「每次都入帳」，單一學生一週答對 10 次 ＝ **+50 幣**，
對照打掃薪水一週 10 幣、商店券 30–60 幣 → 班級經濟會崩。

### 定案

| 項目 | 定案 |
|---|---|
| **抽問／舉手回答** | **不論回答幾次，每生每科每天只算一筆**；事件描述固定寫「**座號N 在○○課舉手回答**」，次數存「次數」欄 |
| **座位加分板** | **單純計次**（格子上顯示次數供師生核對），入帳比照上一列 |
| **合併入庫** | 收班時「同學生 × 同天 × 同工具 × 同類」合併成一列，計數完全保留 |

### 效果

- **唯一動錢的路徑是班規**（`src:"rule"`）。座位板輕點與抽問都是 `src:"tally"`，**不入帳**、
  只累積次數供學習報告的「課堂表現」向度使用。
- **實務量級**：一位學生一天最多 3 科各一筆 → 逐筆 40 筆/天 壓成 ≤ 8 筆/天，
  一學期由約 2,000 筆降到數百筆，Notion 查詢配額壓力解除。
- **拍板 #5 的透明度需求照樣滿足**：投影上看得到次數，學生當場能核對自己被記了幾次。
