## 二、找到的問題

### 🔴 P1（已修）晨掃「打掃缺席」會被記兩次 → 週結多扣一次出勤

**怎麼發生**：老師早上結算送出後，中午發現有人補掃，改了狀態再結算一次。
第一批 id 是 `…-b1-s17-…`、第二批變 `…-b2-s17-…`，**兩個不同 id → R18 兩列都入庫**，
週結的「− 缺席次數」就扣兩次。班規類（△）沒這問題，因為它的 id 本來就不帶批次號。

**根因**：判準寫成「`src` 是不是 tally」，但真正該問的是「**這個事件一天只該有一列嗎**」。
晨掃是狀態式（可以改來改去），抽問是計次式（分兩批要各記各的）——兩者都是 tally。

**修法**：改用 `dedupe:'day'` 標記狀態式事件，晨掃的缺席／支援都帶上。
已驗證：晨掃重送 id 相同（冪等）、抽問兩批 id 仍不同（沒有被誤併）。

### 🔴 P2（規格已補・雲端待同步）金幣寫進 Notion 會靜默失敗

班規的 `coin` 是**字串**且用的是 U+2212 減號（`"−5"`，不是鍵盤上的 `-`）。
紀錄庫「金幣影響」是 **number** 欄——`Number("−5")` 得到 **NaN**，
而 **number 欄收到非數字會整批不進且不報錯**（`RULE_Notion操作限制.md` §5a）。

R18 原本只寫「核對後才寫」，沒說要轉型別。已補：寫入前 `Number(coin.replace("−","-"))`，
轉出 NaN 就記 E07 失敗，**不要寫 0**（0 看起來像「這筆本來就不動錢」）。
另補：比對幣值時是字串比字串，不要先轉數字再比。

### 🟠 P3（規格已補・雲端待同步）「打掃缺席／支援」在 R18 沒有定義

R18 的 tally 標題規則只寫了抽問那一種（「在數學課舉手回答」），
沒有 `subj` 的「打掃缺席」會變成什麼字串**沒有規定**——而週結薪水正是靠這個字串去撈。
類別對照也只寫「tally 依 subj 有值→課堂表現」，`period="環境晨掃"` 的沒有歸屬。

已補：沒有 `subj` 的 tally，**事件描述＝`act` 原文**（「打掃缺席」「打掃支援」），
並註明**這兩個字串是週結的撈取鍵，不可改寫、不可加前綴**；類別歸**生活技能**（與班規③同類）。
另外把「tally 正負向一律寫＋」改成**照 `kind` 寫**——缺席是負向卻不扣幣，
一律寫＋會讓學習報告把缺席讀成正向表現。

### 🟠 P4（規格已補・雲端待同步）逐筆查名冊會燒掉 Notion 查詢配額

一包有 20–30 個座號，R18 原本寫「查名冊取頁面 URL」，照字面會查 30 次。
已補：**處理一包之前先撈一次全班名冊做成對照表，整包共用**。

## 三、通膨試算（前提：符合班規的行為都記錄並加扣點）

**晨掃是週算**（薪水次數×2 在週結一次算），所以「晨掃達標」不逐日入帳——現行設計正確。
因此通膨來源**只剩作業清點的「完成 +5」**。

現行固定收入（全班一週）：職務薪 705 ／打掃 270 ／午餐 120 ／常規獎勵 216 ＝ **1311**

| 方案 | 每人每週淨額 | 倍率 | 150 幣商品要存幾週 |
|---|---|---|---|
| 只有固定薪水 | 37.0 幣 | 1.00 | 4.1 週 |
| 作業完成**只記錄不入帳** | 40.7 幣 | 1.10 | 3.7 週 |
| **作業完成每天 +5**（現行） | **65.7 幣** | **1.78** | **2.3 週** |

作業完成每人每週 **+25 幣**，比職務週薪（25–30）還多出一份。

## 六、重複計算盤點（原則：一個行為一次獎懲）

把「班規獎懲」「工作薪水」「常規獎勵」三條發錢路徑攤開對照，逐條檢查同一個行為會不會被算兩次。

### 🔴 R1（最嚴重）晨掃 △ 第一次就扣 −5，違反既有制度

**既有制度**（班經中心使用說明第 11 條・獎懲連動「一項工作＝一次」）：

> 做一次 **＋2 工作薪水**／**1〜2 次沒做到不扣幣只補做、那幾次沒薪水**／
> **3 次以上 −5**（踩班規③）／表現特別好 ＋10（亮點）。**沒做到先走邏輯後果，不是先扣錢。**

**檢核台現況**：△「到位未達標」→ 當場記班規③bad[0] **−5**。
也就是**第一次沒掃乾淨就扣 5 幣**，而制度說的是「前兩次不扣幣、只是那幾次沒薪水」。

**為什麼會這樣**：設計計畫 §4.6 寫「△ → 班規③ −5」，寫的時候沒有回頭對「1–2 次不扣幣」這條。
兩份規則各自都對，湊起來就變成第一次犯就重罰。

**建議修法（也最符合「本系統只收資料」的分工）**：
△ 改成 **tally「打掃未達標」**（金幣 0），**由週結累計判斷**：同一週 1–2 次 → 不扣幣、那幾次沒薪水；
3 次以上 → 才記班規③ −5。檢核台從此完全不碰錢，三種例外（△／✗／＋）全部只是計次。

### 🔴 R2 作業未交當天補交，現行會扣 −5（牴觸「當天第一次改正不扣點」）

**既有鐵則**（扣幣三鐵則①）：同一天、同一項不當行為，**第一次只要照改正方式做到就不扣點**
（金幣影響填 0，**但行為仍要記一筆**）。

**現況**：作業清點結算時狀態停在「未交」就記 −5。若學生下午補交、老師改成「完成」再重新結算，
**已送出的那筆 −5 已經在紀錄庫**，新結算又多一筆 +5——淨額 0，但紀錄庫留下兩筆互相矛盾的紀錄。

**建議**：作業未交同樣改成 **tally 計次**，扣不扣點在週結時依「當天有沒有補交」判斷；
或維持現況但**約定「收班前才結算」**（補交都處理完再按），並在手冊寫明。

### 🟠 R3 ⑤bad[4]「被記 2 個 × 或提醒 2 次 −10」是累計型，會與個別扣點重複

孩子在課堂被記兩次⑨「干擾上課 −5」（共 −10），老師若再記一筆⑤bad[4]「被記 2 個 × −10」，
**同一組行為就被罰了 −20**。這條班規本質是「累計到門檻的升級處分」，
不該與被累計的那幾筆並存。**建議**：記了⑤bad[4] 就把那兩筆⑨改成金幣 0（保留行為紀錄），
或明訂「⑤bad[4] 只在那兩次都沒扣點時使用」。**檢核台目前兩條都點得到，沒有任何提示。**

### 🟠 R4 幹部職務薪水 vs ⑦good[1]「答應的工作或幹部職務確實完成 +5」

幹部每週已領 25–30 職務薪水（就是為了「把職務做好」）。若再記⑦good[1] +5，
**同一件事付兩次**。**建議**：⑦good[1] 只用在**非幹部的臨時任務**（老師交辦的事），
幹部本職做好由週薪支付。這條**要寫進班規卡的說明**，否則老師與代課老師會各自解讀。

### 🟠 R5 午餐工作薪水 vs ③「餐後整理」

午餐工作已領「次數×2」薪水，而 §4.3 時段對照表把「午餐」也掛在班規③（打掃）底下。
餐後整理做好若再記③good[0] +5，同樣是一件事兩份錢。**建議比照 R4**：本分由薪水支付，
③good[0] 只在**非自己負責的區域**主動幫忙時使用（那本來就是 good[1] +10 的情境）。

### ✅ 已經沒有重複的（確認過）

| 項目 | 為什麼不重複 |
|---|---|
| 打掃薪水 vs 晨掃 ✓ | ✓ 不產生任何事件，本分由薪水支付（現行設計正確） |
| 同一天多份作業未交 | 合併成一列、記「3 次」，金幣只扣一次 |
| 抽問／座位板計次 | `src:"tally"` 一律金幣 0（§6 金幣通膨） |
| 榮譽競賽全班 +10 ＋ 幹部組 +10 | 刻意分開記（理由不同：全班表現 vs 主責職務），非重複 |
| 打掃沒做好 −5 vs 扣薪水 | class-bank 明文「不因為有偏差紀錄就再扣減打掃薪水」 |
| 上課遲到 −5 vs 常規獎勵少 +1 | class-bank 明文「這是不給獎，不是扣錢」 |

### 一句話總結

**會重複的地方，幾乎都在「本分」與「班規正向」的交界**——
本分（打掃、午餐、幹部職務）已經由**工作薪水**支付，班規的 good[0] 又寫著同一件事。
建議統一一條判準：**班規 good[0]（做完本分）不入帳，good[1]（超越本分）才給幣**，
班規卡的文字不必改，只要在記錄端定死這條。

## 七、依老師裁示改版後的結果（2026-09-06 同日）

老師三項裁示：① 晨掃 △ 改計次、週結才判　② 作業「完成」改週算　③ 本分（good[0]）不入帳、超越本分走亮點。

### 改了什麼

| 項目 | 改前 | 改後 |
|---|---|---|
| 晨掃 △ 到位未達標 | 當場記班規③ **−5** | **tally「打掃未達標」金幣 0**，週結累計：1～2 次不扣幣、3 次以上才 −5 |
| 作業「完成」 | 當場記班規④good[0] **+5** | **tally「作業完成」只計次**，週結看全週表現一次給 |
| ⑩重大安全事件 −200 | 與「打斷發言 −5」並排，點了就記 | **幣值 ≥10 一律二次確認**（投影時手滑就是 −200） |

晨掃三種例外現在**全部只計次、都不動錢**——檢核台從此完全不碰金幣，
完全符合「本系統只收資料，加減點在任務處理端算」的分工。

### 同一組亂數種子的前後對照（一週・27 人）

| 指標 | 改前 | 改後 |

| 紀錄庫列數 | 139 | 137 |
| id 重複 | 0 | 0 |

### 順帶抓到的：⑩ −200 的量級

第一輪模擬淨額是 −810，追下去發現是**隨機抽到了 ⑩ 重大安全事件 −200**。
一次誤點 −200 ≒ 全班一週薪水的 1/7、一個孩子四週的收入——
而它在課堂分頁跟 −5 的項目長得一模一樣。已加二次確認（−5 不跳、−10 以上才跳）。
